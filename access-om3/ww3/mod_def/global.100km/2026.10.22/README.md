## Data and Files

### File List

- `mod_def.ww3` — binary model definition for the global 100 km grid.
- `restart.ww3` — compatible binary cold-start file.
- `ww3_grid.nml` — grid definition, input filenames and preprocessing timesteps.
- `namelists_Global.nml` — additional physics, calendar and output settings.
- `OM3_100km.Lat`, `OM3_100km.Lon`, `OM3_100km.Dpt`, `OM3_100km.Mask`,
  `OM3_100km.Obstr` — ASCII grid inputs read by `ww3_grid`.
- `ww3_grid.nml.log` — resolved preprocessing namelist settings.
- `ww3_strt.inp` — cold-start specification (`ITYPE = 3`, fetch-limited JONSWAP).
- `GenGrid.py` — grid-input generation script; see the provenance caveat below.

### Data Specific Information

The grid is a 360 × 324 spherical curvilinear grid with tripolar closure.
The spectrum has 25 frequencies and 24 directions, with frequency ratio
`XFR = 1.10`. The additional namelist settings are:

- `CALTYPE = '365_day'`.
- `SINA0 = 0.04` in SIN6.
- `SWLB1 = 0.22E-03`, `CSTB1 = T` in SWL6.
- `LAMBDA = 0.237`, `NLPROP = 2.13E+07` in SNL1.
- `E3D = 1`, `USSP = 1`, `IUSSP = 3`,
  `STK_WN = 0.04, 0.110, 0.3305`, `STK_TAIL = T` in OUTS.
- `LMPENABLED = F`, `HSLMODE = 0` in LMPN.
- `CICE0 = 0.25`, `CICEN = 0.75`, `FLAGTR = 4`, `ICNUMERICS = T` in MISC.
- `IC4METHOD = 8` in SIC4.

The timestep changes relative to the existing October model definition are:

| Preprocessing setting | Runtime setting in `wav_in` | Previous (s) | New (s) |
| --- | --- | ---: | ---: |
| `DTMAX` | `dtmax` | 900 | 1800 |
| `DTXY` | `dtcfl` | 300 | 600 |
| `DTKTH` | `dtcfli` | 600 | 600 |
| `DTMIN` | `dtmin` | 10 | 50 |

These are WW3 integration controls, not the component coupling interval.
This update only makes the preprocessing timestep values consistent with
the existing runtime values in
[`wav_in` at commit `dbd6a107`](https://github.com/ACCESS-NRI/access-om3-configs/blob/dbd6a107bd821bfe87d1e3ac762cd65fc46dcc6c/wav_in#L1-L8).
The runtime namelist and its timestep choices were unchanged.

## Methodological information

The binaries were generated locally on 2026-10-22. The preprocessing log
records the new timestep values above. The configuration selects
`access-om3/2026.05.004`; however, the available log does not identify the
executable or module actually used to generate these files. Confirm and
record that executable provenance before publishing the inputs.

`GenGrid.py` currently references topography dated `2026.04.07`, whereas
`config.yaml` references topography dated `2026.10.13`. Do not assume that
rerunning this script reproduces the supplied ASCII grid inputs without
first checking its source paths. The binary comparison below confirms that
this regeneration did not change the grid data stored in `mod_def.ww3`.

### Binary verification

Compared byte-for-byte with the October files listed above:

- `mod_def.ww3`: 4,820,185 bytes, unchanged size. Only five bytes differ,
  all within the four-value timestep block. Decoding that block as
  big-endian 32-bit floating-point values confirms the changes in the
  table. Every byte outside the timestep block is identical.
- `restart.ww3`: 2,400 bytes; byte-for-byte identical to the existing file.
  No replacement is needed solely for this timestep update.

SHA-256 checksums of the generated files:


This verification establishes the binary differences; it is not a model
run or a runtime compatibility test.
